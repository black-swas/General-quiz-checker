# Polyglot & C Lab Quiz Evaluator (v4.1.0 — Production Edition)

Universal LLM-primary and polyglot triage platform for programming and general quizzes at **IISER Bhopal (Data Science & Engineering)**.
It supports **25+ programming and written languages** (`.c`, `.cpp`, `.py`, `.ipynb`, `.java`, `.js`, `.ts`, `.rs`, `.go`, `.sql`, `.r`, `.sh`, `.jl`, `.txt`, `.md`, `.tex`, …) with the exact same ZIP format, upload structure, and single-page web interface:

* **Primary 4-Way AI Triage (`claude-haiku-5-5`, fallback `claude-haiku-4-5-20251001`)**: Evaluates submissions across any programming language, function-only solution, SQL query, or written/rubric question and classifies them into **Needs review (`RED`)**, **Creative approach (`BLUE`)**, **Clear (`GREEN`)**, or **Unverified (`GRAY`)**, while hard deterministic integrity flags remain locked.
* **Deterministic Integrity & Plagiarism Guardrails**: Runs pairwise canonical structural & prose plagiarism (`STRONG` vs `WEAK` with minority-language cohort protection and cross-question collusion corroboration), cross-question stylometric shift detection, Trojan Source / homoglyph scanning (`CVE-2021-42574`), prompt-injection detection, stub detection, and static complexity/spoofing analysis.
* **Polyglot OS Sandbox (`gcc`, `g++`, `python3 -I -B`, `bash`, `node`)**: When runnable test cases and a local runtime exist (and the submission is a full program rather than a function-only snippet), executes tests under `prlimit` with float-tolerance matching and failure-mode diagnosis (`OFF_BY_ONE`, `INTEGER_OVERFLOW`, `SEGFAULT`, `FLOATING_POINT_EXCEPTION`, `CASE_OR_FORMAT_MISMATCH`).
* **College-Scale Production Resilience**: Persists completed evaluations and TA overrides to SQLite (`/app/data/hitl_calibration.db`), automatically resumes running or finished jobs across browser refreshes (`F5`), supports job cancellation, filters out IDE scratch files (`tempCodeRunnerFile.*`, `.vscode`, `.ipynb_checkpoints`), and scales up to 250 students per batch.

## Deploy on Render Free Plan (100% Free Tier Optimized)

This platform is optimized to run smoothly within **Render's Free Tier (512 MB RAM, shared CPU, ephemeral disk, sleep after 15m inactivity)**.

1. **Deploy via Blueprint**:
   - Push this repository to GitHub.
   - In Render Dashboard: **New +** → **Blueprint** → select your repository.
   - Render automatically reads `render.yaml` (`plan: free`) and builds the Docker container.
2. **Environment Variables**:
   - **`ANTHROPIC_API_KEY`**: Paste your Anthropic API key in Render Dashboard under Environment.
   - **`API_AUTH_TOKEN`**: Automatically generated by Render (or set your own password). Share this token with your TAs/graders.
   - **`RENDER`**: Render sets `RENDER=true` automatically, triggering low-memory optimization mode.
3. **Optimizations Active on Free Plan**:
   - **512 MB RAM Guard**: Concurrency is automatically clamped to 2 sandbox workers and 3 LLM workers, with C/C++ memory limits clamped to 256 MB and Python to 384 MB to completely eliminate container OOM kills (`SIGKILL 137`).
   - **Zero-RAM Spooling**: Student ZIP archives (up to 50 MB) stream in 64 KB chunks directly to temporary files on disk, preventing memory ballooning during 200+ student uploads.
   - **100s Request Timeout Immunity**: Evaluations run as asynchronous background jobs with polling (`/api/jobs/{id}`) and exponential backoff reconnection, ensuring college Wi-Fi blips and Render cold wakeups never abort in-flight evaluations.
   - **Single-Question Auto-Mapping**: In 1-question lab exams, student submissions named `25104.c`, `25104.py`, or `rollno.cpp` automatically map to `Q1` without false rejection.
   - **Comment Header Recovery**: If students name a file `submission.c` or `main.py`, the system detects question headers (`// Question 2`) and student identities (`// Roll No: 25104`) in leading comments.
   - **Garbage Collection & Ephemeral SQLite**: Automated `gc.collect()` after evaluation runs and database fallback to `/tmp/hitl_calibration.db` ensure the container stays responsive and never crashes due to missing disk mounts.
   - *(Optional Upgrade)*: If you upgrade to `plan: starter`, you can uncomment the `disk:` block in `render.yaml` to enable persistent disk storage across restarts.
