    1. Question Paper JSON Schema

    A question paper JSON defines the course code, quiz title, default language, and questions. Questions can include sample & hidden test cases, float tolerances, forbidden constructs, and grading rubrics for AI triage.

    Standard Fields:
    • course_code: Course ID (e.g. "DSE-201").
    • quiz_title: Title of exam or quiz.
    • question_id: Target ID matching student filenames ("Q1", "que1", "1").
    • execution_mode: "auto" (runs tests if present), "sandbox" (enforce compile & run), "llm_only" (written/rubric tests), or "static_only".
    • is_sample: Set to true for visible sample test cases, false for hidden test cases. (Students passing only samples are flagged for hardcoding!)
    • forbidden_constructs: Keywords or regex banned from code (e.g. ["goto", "eval", "qsort"]).
    • float_rel_tol / float_abs_tol: Numerical tolerance for floats & scientific notation (default: 1e-6).

    2. Dataset Creation & Packaging Guide
    
        
    The ingestion engine handles whatever naming students used with zero manual TA renaming required:
    
        
    
          
    
            
    🎓 Moodle Direct ZIP (Zero Renaming)
    
            
    Download all submissions directly from Moodle. The folder structure Student Name_12345_assignsubmission_file_/que1.c is automatically parsed.
    
          
    
          
    
            
    📁 Folder per Student
    
            
    Master ZIP with 25104/q1.c and 25104/q2.py. Sub-zips (25104.zip inside the archive) are also unpacked recursively.
    
          
    
          
    
            
    📄 Flat Loose Files
    
            
    All student files mixed in root: 25104_q1.c, 25104_que2.py, q1_25104.cpp.
    
          
    
          
    
            
    ⚡ 1-Question Exam Auto-Mapping
    
            
    If the exam has only 1 question, files named 25104.c, 25104.py, or rollno.cpp map to Q1 automatically!
    
          
    
          
    
            
    🏷️ Comment Header Fallback
    
            
    If files are named main.c, comments like // Roll No: 25104, Question: 1 or # Student: 25104 are parsed.
    
          
    
          
    
            
    📓 Jupyter Notebooks (.ipynb)
    
            
    Python code cells in .ipynb files are extracted in chronological order and evaluated as Python scripts.
    
          
    
        
    
        
    Auto-cleaned junk: Precompiled binaries (a.out, .exe, .class), IDE files (.vscode, .idea, tempCodeRunnerFile.*), and OS artifacts (__MACOSX, .DS_Store) are automatically stripped.
    
      
    

      
      
    
        
    3. Grading Queues & TA Workflow
    
        
    The platform separates submissions into 4 clear queues for high TA productivity:
    
        
      
          
    • GREEN (Clear): Standard, correct solution passing tests or meeting rubric. No integrity flags.
      • 
          
    • BLUE (Creative approach): Correct solution with an innovative, distinctive, or advanced algorithm detected by the AI evaluator or AST analyzer.
      • 
          
    • RED (Needs review): Flagged for compiler errors, test failures, timeouts, hardcoded sample spoofing, structural plagiarism, or prompt injection.
      • 
          
    • GRAY (Unverified): Awaiting manual review or languages without a local sandbox runtime.
      • 
        
    
        
    Human-in-the-Loop (HITL) Calibration:
    
        
    TAs can override any verdict with one click. Overrides and comments are stored in the server SQLite database. Future evaluation runs inject these past decisions into Claude's prompt so the AI calibrates to your grading standards!
    
        
    Exporting Results:
    
        
    Download a consolidated Gradebook CSV ready for immediate import into Moodle or Google Classroom, or save the complete session JSON for archival.
    
      
    

      
      
    
        
    4. High-Speed Architecture (Zero Accuracy Loss)
    
        
    The system is engineered to evaluate 200+ students in minutes without compromising evaluation accuracy:
    
        
      
          
    • In-Memory SHA-256 Verification Cache: Duplicate submissions (identical templates, empty files, identical solutions) are verified once; subsequent identical submissions receive cached results in 0.0001s.
      • 
          
    • Native AST Python Syntax Check: In-memory compilation bypasses subprocess overhead, validating syntax in 0.1ms.
      • 
          
    • Anthropic Prompt Caching: The system prompt (rubric, problem statement, instructions) is marked with cache_control: ephemeral, accelerating batches by ~70% and slashing token costs by 90%.
      • 
          
    • Plagiarism Disjoint Filtering: Exact token stream identity bypasses SequenceMatcher; disjoint 5-token shingles skip set unions.
      • 
          
    • Zero-RAM Disk Spooling: ZIP uploads stream in 64 KB disk buffers, keeping memory footprint strictly under 512 MB on Render Free plan.
